# Description

The crates.io RC removed scxsim-build's per-.so vmlinux_override parameter (scx_include_paths / SimBuildInputs::include_paths / build_bundled). It was unsound: scx_simulator's host static libraries (sim_task.c via sim_wrapper.h -> scx/common.bpf.h -> vmlinux.h) are always compiled against the vendored header, and they allocate the task_struct, cgroup, css_set, kernfs_node and task_group the scheduler reads. The sim has no CO-RE relocation (the __builtin_preserve_* builtins are compiled out), so a .so compiled against any other vmlinux.h reads the host's structs at the wrong offsets.

Measured 2026-09-24 on 17 offsetof/sizeof probes. Vendored x86 v7.2-rc6 vs the 7.1.3 kernel on the dev host: 15 differ. Vendored x86 vs vendored arm64, same kernel commit: 8 differ (task_struct pid/cpus_ptr/cgroups/comm/sizeof, sizeof(cgroup), css_set.dfl_cgrp). End to end: with the 7.1.3 header the .so does not compile (no struct scx_cmask), which is loud. With the arm64 header it compiles: simple runs with an identical fingerprint (it touches only sched_ext_entity, whose layout matches), while lavd, mitosis and cosmos die with SIGSEGV (lavd in lavd_init_task at p->real_parent->pid) and print no diagnostic. A header whose differences fall only on non-pointer fields would read wrong integers without faulting. That case follows from the mechanism but was not measured.

A sound design needs both of these:
(1) The override is a property of the WHOLE build. Pass it the way SCX_ROOT is passed: an env var read by scx_simulator's build.rs, with the resolved dir published as DEP_SCXSIM_VMLINUX metadata. Then the host static libs and every .so compile against one header. Separately, check the Rust side's hardcoded enum/flag values against the header; those do not follow a header switch.
(2) A load-time identity check. Hash the resolved vmlinux.h, pass the hash as -D to both the host compile and each .so compile, and have DynamicScheduler refuse a mismatch with a new LoadError variant naming both headers. This is the same pattern as the host-export probe (LoadError::HostSymbolsNotExported). It also catches a .so built by a different scx_simulator build.

Until this lands, an embedder has no supported way to compile against the kernel under test's vmlinux. In the sim the kernel is the sim, so the vendored header is the correct one for every in-process use.
