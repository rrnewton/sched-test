# Description

replay_bp_handler fires when execution hits the target RIP, but does NOT verify that the current RBC matches target.rbc_count. If the instruction executes multiple times (loops), we preempt on the wrong dynamic instance.

Similarly, replay_pmu_handler does NOT check whether the PMU signal overshot the target. It blindly arms the HW breakpoint without verifying that the current RBC is still below target.rbc_count. If PMU skid caused the signal to fire past the target, the breakpoint may never fire (if the target instruction already executed) or may fire on a later invocation, corrupting the replay.

Required changes:

In replay_pmu_handler: After the PMU timer fires, read current RBC. If current_rbc > target.rbc_count, the PMU overshot — set an overshoot flag and do NOT arm the breakpoint. If current_rbc <= target.rbc_count, arm the breakpoint as normal (we're close but haven't passed the target yet).

In replay_bp_handler: After the breakpoint fires, read current RBC via read_rbc_count(timer_fd). If current_rbc < target: re-enable breakpoint and return (wrong instance). If current_rbc >= target: preempt.

Invariants:
1. ASYNC-SIGNAL-SAFETY: All ops in SIGTRAP handler must be signal-safe
2. RBC COUNTER SEMANTICS: rbc_count is relative to last PERF_IOC_RESET, not cumulative
3. BREAKPOINT RE-ENABLE: On wrong instance, PERF_IOC_ENABLE and return without yielding token
4. OVERSHOOT TOLERANCE: current_rbc > target is OK (closest we can get), log warning
5. TIMER_FD ACCESS: REPLAY_CTX has timer_fd, verify no interference with PMU handler
6. BREAKPOINT-ONLY MODE: In --no-pmu-signal, breakpoint fires on every invocation, RBC check is sole selection mechanism
7. NO PRNG IN RETRY: Wrong-instance returns must not consume PRNG, yield tokens, or modify interleave state

Testing: Update test_replay_determinism (currently #[ignore]) to verify deterministic replay.
