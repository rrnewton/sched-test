# Description

A finite (RepeatMode::Once) task in a bandwidth-throttled cgroup under LAVD (enable_cpu_bw=true) emits TaskCompleted multiple times and over-runs its total work. Repro: 3x Run(40ms) Once tasks in a tight cgroup (cpu.max 10ms/100ms) on 1 CPU, LAVD enable_cpu_bw=true, 5s -> TaskCompleted pids=[3,2,2,2,1] (5 completions for 3 tasks; pid 2 completes 3x); total_runtime ~52-58ms each (work=40ms). Control (identical tasks, UNLIMITED cgroup, 1 CPU): each completes exactly once, rt ~45-50ms (mild slice-granularity over-run only). So the EXTRA completions are throttle-specific: when a finite task is put aside (LavdBailOnCgroupThrottle) and re-enqueued on replenish (CgroupBwReenqueueOnReplenish), its finite phase appears to restart/re-complete rather than honoring RepeatMode::Once. Impact: finite-workload completion assertions under throttle unreliable; potential runtime over-accounting. The 'no task lost' invariant still holds (every pid completes >=1). Found writing tg test-lavd-cpu-bw-stall-repro; tests/cgroup_bw_stall_completion.rs asserts the robust weak invariant and references this issue.
