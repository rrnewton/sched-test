# Description

The lavd scxsim wrapper (schedulers/lavd/wrapper.c::lavd_setup) hardcodes is_smt_active=false and nr_llcs=1 (uniform, non-SMT topology). Consequently idle.bpf.c::migrate_to_neighbor is unreachable: its primary call site (idle.bpf.c:872) is gated on !i_smt_empty, requiring is_smt_active AND a fully-idle SMT core. Even when is_smt_active is forced true (whitebox) with scenario.smt(2) providing a real idle-SMT-mask substrate and a strongly imbalanced two-domain workload, the required simultaneous state (selected task sticky to a stealee domain with no fully-idle core while a neighbor has a fully-idle core, at the select_cpu instant) did not co-occur (0% via coverage.sh). Site idle.bpf.c:897 needs LAVD_FLAG_MIGRATION_AGGRESSIVE, set only by set_aggressive_migration via an execve tracepoint the sim does not deliver. Work: propagate scenario.smt() into the lavd wrapper is_smt_active + per-CPU SMT sibling topology; add a stealee/idle-neighbor scenario primitive. Found by tg cover-lavd-power-idle-gaps. Related sim-5a20c.
