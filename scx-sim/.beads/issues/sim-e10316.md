# Description

The sim delivers wake_flags = SCX_ENQ_WAKEUP(0x1) | SCX_WAKE_SYNC(0x10) for waker-driven wakes (engine.rs ~3535) but never sets SCX_WAKE_TTWU(0x8). In the kernel SCX_WAKE_TTWU is set for try_to_wake_up() wakeups (the common case). Schedulers that gate logic on is_wakeup(wake_flags)==(wake_flags & SCX_WAKE_TTWU) therefore never take those paths under sim.

Concrete impact (cosmos, COVERAGE_AUDIT_20260722.md sec 4.2): cosmos pick_idle_cpu()'s wakeup 'move wakee toward the faster waker' block (main.bpf.c ~858) is guarded by is_wakeup(wake_flags), so is_cpu_faster() and cpus_share_cache() run 0% even with an asymmetric-capacity topology + waker/wakee workload (test_heterogeneous_capacity). Fix: set SCX_WAKE_TTWU on ttwu-style wakeups (in addition to SCX_WAKE_SYNC for sync wakes). NOTE: this changes wake_flags seen by ALL schedulers, so it needs full-suite revalidation (lavd/cosmos/mitosis wake tests). Filed during tg write-cosmos-tests.
