# Description

COSMOS's LLC-awareness (cpus_share_cache -> cpu_llc_id, scheds/include/scx/percpu.bpf.h DEFINE_PER_CPU_VAL_FUNC(cpu_llc_id,int,sd_llc_id)) reads the weak __ksym 'sd_llc_id', which is NOT wired in the scxsim substrate (no writer in scx-sim/crates/scx_simulator/src). Result: cpu_llc_id() returns -ENOENT for every CPU, so cpus_share_cache(a,b) is always true — the simulator presents a SINGLE LLC to cosmos regardless of the scenario's cpus_per_llc setting. cosmos's actual DSQ 'domains' under sim are NUMA-node based (shared_dsq = numa_enabled ? cpu_node(cpu) : SHARED_DSQ).

IMPACT (tg test-cosmos-llc-scheduling): genuine per-LLC (sub-NUMA cache-domain) placement/balancing/idle-selection/stealing for COSMOS cannot be tested — such tests would actually exercise NUMA-node behavior and mislabel it as LLC. cpus_per_llc currently only affects LAVD (engine sets cpus[i].llc_id, used by lavd balance paths and cpu_migration.rs test_cross_llc_migration_lavd), not cosmos.

FIX: populate per-CPU sd_llc_id in the substrate from scenario.cpus_per_llc (mirror the engine's cpus[i].llc_id, engine.rs build_cpus), so cpu_llc_id(cpu) returns the real LLC id and cpus_share_cache distinguishes LLCs. Then genuine cosmos LLC-aware tests (task placement within an LLC, cross-LLC stealing, LLC-boundary idle selection) become possible. Filed during tg test-cosmos-llc-scheduling.

# Notes

cosmos_llc.rs (commit b6ce868, tg test-cosmos-llc-scheduling) now tests COSMOS's genuine NUMA-node domain model (per-node DSQ routing, per-node load-balance fairness, node-local wake placement, cross-domain stealing, engine cross-LLC migration-cost path). Genuine sub-NUMA per-LLC COSMOS placement/stealing tests remain BLOCKED on this issue (+ sim-e10316). When sd_llc_id is wired, extend cosmos_llc.rs with real per-LLC assertions (helpers cross_llc_migrations/inserted_dsq_ids already present).
