## Sensitivity Analysis

### Key Findings

1. **E2E latency is stable across configs** — Both schedulers produce nearly identical
   E2E latencies (~1086-1093 µs for foreground, varying by workload for background).
   The ~6 µs gap (LAVD lower) is consistent across all configs. This is because
   E2E latency is dominated by the workload's run+sleep cycle (500µs + 500µs sleep),
   and scheduling overhead is a small fraction.

2. **Scheduling latency (Sched P99) is the differentiator** — Tickless consistently
   achieves lower scheduling P99 than LAVD:
   - Baseline: Tickless 34.9 µs vs LAVD 64.6 µs (1.85× better)
   - Light: Tickless 29.3 µs (LAVD data missing)
   - Heavy: Tickless 37.5 µs (LAVD data missing)

3. **CPU utilization differs dramatically** — Tickless reports 89-94% CPU utilization
   across all configs, while LAVD reports 18-37%. This likely reflects different
   scheduling strategies: Tickless keeps CPUs busy, while LAVD may idle CPUs more
   aggressively (power-saving orientation).

4. **Background thread count has limited impact** — Moving from 4→16→32 BG threads
   doesn't significantly change foreground E2E latency for either scheduler.
   The schedulers handle contention well at these ratios.

5. **Core count scaling** — Going from 8→16 cores with proportionally more threads
   (20→36) slightly increases Tickless sched P99 (34.9→37.5 µs) but maintains
   similar E2E performance. The scheduling overhead cost of more cores is minimal.

### Most Sensitive Parameters

1. **Scheduler choice** — The biggest effect is on CPU utilization strategy and
   scheduling latency P99. Tickless trades higher CPU usage for lower tail latency.
2. **Background thread ratio** — Minimal impact on foreground latency, but affects
   background thread E2E latency (bg_hog E2E varies from 1202-2010 µs depending on config).
3. **Core count** — Low sensitivity at these workload sizes. Both schedulers scale well.
